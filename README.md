# Вектор — управление выездными работами

Интерактивный адаптивный прототип: 30 экранов для сотрудника, диспетчера и руководителя, а также каталог всех страниц. Интерфейс на русском языке.

## Запуск

Проект использует обычные HTML, CSS и JavaScript. Установка npm-пакетов и сборка не требуются.

Из папки проекта выполните:

```bash
python3 -m http.server 8000 --directory dist
```

Откройте `http://localhost:8000` в браузере. Для этой команды нужен Python 3. На Windows можно использовать `py -m http.server 8000 --directory dist`.

## Как смотреть макет

На стартовом экране откройте «Регистрация компании». После регистрации на экране «Команда» появится ссылка компании. Добавьте сотрудника с логином и временным паролем, затем откройте ссылку в этом же браузере или вставьте её в форму входа. Сотрудник задаёт личный пароль при первом входе, затем выбирает PIN или биометрию. Владелец входит по рабочей почте и паролю.

Если сотрудник забыл пароль, в его карточке владелец нажимает «Сбросить пароль» и передаёт сотруднику новый временный пароль. При следующем входе сотрудник снова задаёт личный пароль.

Сценарий регистрации и входа работает локально с одной компанией на профиль браузера. Ссылка использует данные того же адреса и профиля браузера. PIN и биометрия представлены демонстрационным сценарием.

В верхней панели выберите роль: «Сотрудник», «Диспетчер» или «Руководитель». Значок телефона включает мобильный предпросмотр. Кнопка «Все экраны» открывает каталог страниц. На небольшом экране адаптация включается автоматически.

Основной сценарий: сотрудник открывает заявку №1042, завершает чек-лист, добавляет демонстрационное фото «После» и отправляет результат. Руководитель видит работу в очереди приёмки и может принять её или вернуть на доработку.

Демонстрационное состояние сохраняется в localStorage браузера. Чтобы вернуть исходные данные, откройте «Все экраны» → «Начать заново» → «Сбросить макет».

## Загрузка в GitHub

### Через сайт

1. Создайте репозиторий `vektor-field-prototype`. Для закрытого доступа выберите Private.
2. Распакуйте архив и откройте папку `vektor-field-prototype`.
3. В новом пустом репозитории нажмите ссылку **uploading an existing file**. Если репозиторий уже содержит файлы, используйте **Add file → Upload files**.
4. Загрузите содержимое папки проекта, сохраняя папку `dist`, и подтвердите **Commit changes**.

### Через Git

Для следующего способа нужен установленный Git и настроенная авторизация GitHub на вашем компьютере. Создайте новый пустой репозиторий без README, лицензии и .gitignore, поскольку файлы уже подготовлены локально.

В терминале откройте распакованную папку проекта и выполните:

```bash
git init
git add README.md .gitignore dist
git commit -m "Initial commit: Vektor responsive prototype"
git branch -M main
git remote add origin https://github.com/YOUR_USERNAME/vektor-field-prototype.git
git push -u origin main
```

Замените `YOUR_USERNAME` на ваш логин GitHub. Если имя репозитория отличается, замените и его. URL можно скопировать со страницы вашего репозитория.

Если репозиторий уже содержит коммиты, сначала клонируйте его и скопируйте файлы проекта в полученную папку. Затем создайте обычный коммит и выполните push.

Официальная инструкция: [добавление локального проекта в GitHub](https://docs.github.com/ru/migrations/importing-source-code/using-the-command-line-to-import-source-code/adding-locally-hosted-code-to-github), [загрузка файлов через сайт](https://docs.github.com/ru/repositories/working-with-files/managing-files/adding-a-file-to-a-repository).

## Границы прототипа

Это демонстрационный интерфейс с вымышленными данными. Реальные камера, GPS, авторизация, серверная синхронизация, обработка Excel и уведомления требуют отдельной реализации. Изменения выполняются локально в браузере; взаимодействия между разными устройствами нет.

В CSS подключён шрифт Manrope из Google Fonts. Если он недоступен, используется системный шрифт. Остальные ресурсы находятся в `dist` и подключаются относительными путями.

## Проверка

В исходной версии проверены синтаксис JavaScript, все 30 экранов в мобильном предпросмотре, отправка работы на приёмку, принятие руководителем, создание заявки и разрешение демонстрационного конфликта данных.
